## TypeScript 타입 총정리 — 원시 타입부터 특수 타입까지

### 왜 타입을 알아야 하나?

TypeScript를 쓰는 이유는 변수에 어떤 값이 들어올 수 있는지 **컴파일 시점에 제한**하기 위해서다. 그 출발점이 기본 타입이며, 여기서 배열, 객체, 특수 타입으로 확장된다.

### 타입 체계 도식도

TypeScript의 주요 타입이 어떤 계층으로 구성되는지 한눈에 보면 다음과 같다.

```
TypeScript 타입
├── 원시 타입 (Primitive)
│   ├── number
│   ├── string
│   ├── boolean
│   ├── null
│   └── undefined
│
├── 리터럴 타입 (Literal)
│   ├── 숫자 리터럴    (예: 10)
│   ├── 문자열 리터럴   (예: "hello")
│   └── 불리언 리터럴   (예: true)
│
├── 복합 타입
│   ├── 배열           number[], Array<string>
│   ├── 튜플           [number, string] — 길이·위치별 타입 고정
│   ├── 객체 리터럴 타입  { id: number; name: string }
│   │   ├── 선택적 프로퍼티   id?: number
│   │   └── readonly 프로퍼티  readonly apiKey: string
│   ├── 타입 별칭       type User = { ... }
│   ├── 인덱스 시그니처   { [key: string]: string }
│   └── enum           enum Role { ADMIN, USER }
│
└── 특수 타입
    ├── any            타입 검사 포기 (지양)
    ├── unknown        안전한 any — 타입 좁히기 필요
    ├── void           반환값 없음
    └── never          반환 자체가 불가능
```

---

### 원시 타입 (Primitive Type)

원시 타입은 **하나의 값만 저장**하는 타입이다. `number`, `string`, `boolean`, `null`, `undefined` 다섯 가지가 있다.

`number` 타입은 일반적인 숫자 외에 특수 값도 포함한다.

```typescript
let num1: number = Infinity;
let num2: number = -Infinity;
let num3: number = NaN;          // 이 셋 모두 number 타입에 속한다
```

#### null 할당이 필요할 때

기본 설정에서는 `number` 타입에 `null`을 할당할 수 없다.

```typescript
let numA: number = null;  // ❌ 기본 설정에서는 에러
```

`tsconfig.json`에서 `strictNullChecks`를 `false`로 설정하면 허용된다. 단, 프로젝트 전체에서 null 안전성 검사가 비활성화되므로 주의가 필요하다.

---

### 리터럴 타입 (Literal Type)

리터럴 타입은 **특정 값 자체**를 타입으로 사용하는 것이다. "리터럴 = 값"이라고 생각하면 된다.

```typescript
let numA: 10 = 10;
numA = 12;  // ❌ 에러 — 타입이 10이므로 10만 할당 가능
```

`number`는 "아무 숫자나 가능"이지만, `10`은 "오직 10만 가능"이다. 타입의 범위를 극단적으로 좁히는 방식이다.

#### 리터럴 타입은 언제 쓰나?

단독으로는 쓸모가 제한적이지만, **유니온 타입**과 결합하면 허용 가능한 값의 목록을 정의할 수 있다.

```typescript
type Direction = "up" | "down" | "left" | "right";

let move: Direction = "up";         // ✅
let wrong: Direction = "diagonal";  // ❌ 네 가지 중 하나만 가능
```

### 배열

배열 타입을 선언하는 두 가지 방식이 있다.

```typescript
// 1번 방식: 타입[]
let numArr: number[] = [1, 2, 3];
let strArr: string[] = ["hello", "world"];

// 2번 방식: Array<타입> (제네릭)
let boolArr: Array<boolean> = [true, false, true];
```

요소의 타입이 여러 가지라면 유니온 타입을 사용한다.

```typescript
let multiArr: (number | string)[] = [1, "hello"];
```

다차원 배열은 `[]`를 중첩한다.

```typescript
let doubleArr: number[][] = [
  [1, 2, 3],
  [4, 5],
];
```

---

### 튜플 (Tuple)

튜플은 **길이와 각 위치의 타입이 고정된 배열**이다. 일반 배열과 달리 "몇 번째에 어떤 타입이 오는지"를 지정할 수 있다.

```typescript
let tup1: [number, number] = [1, 2];
let tup2: [number, string, boolean] = [1, "2", true];
```

컴파일된 JavaScript에서는 일반 배열로 변환된다. 튜플은 TypeScript에서만 존재하는 개념이다.

```javascript
// 컴파일 결과
let tup1 = [1, 2];
let tup2 = [1, "2", true];
```

### 객체

#### `object` 타입의 한계

`object`로 타입을 명시하면 "이건 객체다"라는 것만 알려줄 뿐, 내부 프로퍼티에 접근할 수 없다.

```typescript
let user: object = {
  id: 1,
  name: "bysu",
};

user.id;  // ❌ 에러 — object 타입은 프로퍼티 정보를 모른다
```

#### 객체 리터럴 타입

프로퍼티의 타입까지 명시하면 안전하게 접근할 수 있다. 이를 **객체 리터럴 타입**이라 한다.

```typescript
let user: {
  id: number;
  name: string;
} = {
  id: 1,
  name: "bysu",
};

user.id;  // ✅ 접근 가능
```

#### 선택적 프로퍼티 (`?`)

특정 프로퍼티가 없어도 되는 경우 `?`를 붙인다.

```typescript
let user: {
  id?: number;    // 있어도 되고 없어도 됨
  name: string;
} = {
  name: "bysu",  // ✅ id 없이도 가능
};
```

#### 읽기 전용 프로퍼티 (`readonly`)

값이 수정되면 안 되는 프로퍼티에는 `readonly`를 붙인다.

```typescript
let config: {
  readonly apiKey: string;
} = {
  apiKey: "MY API KEY",
};

config.apiKey = "fu";  // ❌ 에러 — readonly 프로퍼티는 수정 불가
```

### 타입 별칭 (Type Alias)

같은 객체 구조를 여러 변수에 반복 작성하는 건 비효율적이다. `type` 키워드로 이름을 붙여 재사용할 수 있다.

```typescript
type User = {
  id: number;
  name: string;
};

let user: User = {
  id: 1,
  name: "bysu",
};

let user2: User = {
  id: 2,
  name: "someone",
};
```

---

### 인덱스 시그니처 (Index Signature)

프로퍼티의 key와 value가 일정한 규칙을 따를 때, 모든 프로퍼티를 일일이 나열하지 않고 **규칙 자체를 타입으로 정의**하는 방식이다.

```typescript
// 모든 key가 string, 모든 value도 string인 객체
type CountryCodes = {
  [key: string]: string;
};

let countryCodes: CountryCodes = {
  Korea: "ko",
  UnitedState: "us",
  Japan: "jp",
  // 얼마든지 추가 가능
};
```

특정 프로퍼티를 필수로 강제하고 싶다면 함께 명시한다.

```typescript
type CountryCodes = {
  [key: string]: string;
  Korea: string;           // Korea는 반드시 있어야 함
};
```

### enum 타입

관련된 상수를 하나의 그룹으로 묶을 때 사용한다.

```typescript
enum Role {
  ADMIN = 0,
  USER = 1,
  GUEST = 2,
}

const user1 = {
  name: "bysu",
  role: Role.ADMIN,  // 0
};
```

enum은 컴파일해도 사라지지 않고 **JavaScript 객체로 변환**된다. 이 점이 `type`이나 `interface`와 다르다.

### any와 unknown

#### `any` — 타입 검사 포기

어떤 타입이든 할당할 수 있고, 어디에든 넣을 수 있다. 사실상 타입 검사를 하지 않으므로 TypeScript를 사용하는 의미가 사라진다. **최대한 지양**해야 한다.

#### `unknown` — 안전한 any

`any`처럼 아무 값이나 넣을 수 있지만, 다른 타입 변수에 바로 할당할 수 없다.

```typescript
let unknownVar: unknown;

let num: number = 10;
num = unknownVar;  // ❌ 에러 — unknown을 number에 바로 넣을 수 없다
```

**타입 좁히기(type narrowing)**를 거쳐야 사용할 수 있다.

```typescript
if (typeof unknownVar === "number") {
  num = unknownVar;  // ✅ 타입이 확인되었으므로 가능
}
```

`any`보다 `unknown`을 사용하면 실수로 타입이 섞이는 것을 방지할 수 있다.

---

### void와 never

#### `void` — 반환값이 없음

함수가 아무것도 반환하지 않을 때 사용한다.

```typescript
function log(msg: string): void {
  console.log(msg);
}
```

#### `never` — 반환이 불가능함

함수가 정상적으로 종료될 수 없는 경우에 사용한다. `void`는 "반환값이 없다"이고, `never`는 "반환 자체가 불가능하다"이다.

```typescript
// 무한 루프 — 함수가 끝나지 않는다
function infinite(): never {
  while (true) {}
}

// 항상 에러를 던짐 — 정상 반환이 불가능하다
function throwError(): never {
  throw new Error("에러 발생");
}
```

---

### 정리

| 분류 | 타입 | 핵심 |
|---|---|---|
| 원시 | `number`, `string`, `boolean`, `null`, `undefined` | 하나의 값을 저장 |
| 리터럴 | `10`, `"hello"`, `true` | 특정 값만 허용 |
| 배열/튜플 | `number[]`, `[number, string]` | 튜플은 위치별 타입 고정 |
| 객체 | 객체 리터럴 타입, 타입 별칭 | `?`로 선택, `readonly`로 보호 |
| 인덱스 시그니처 | `[key: string]: string` | key-value 규칙 정의 |
| enum | `enum Role { ... }` | JS 객체로 컴파일됨 |
| 특수 | `any` < `unknown` < 구체 타입 | unknown이 any보다 안전 |
| 반환 | `void` vs `never` | 반환 없음 vs 반환 불가능 |
