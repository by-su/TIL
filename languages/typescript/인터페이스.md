## TypeScript 인터페이스 — 객체 구조에 이름을 붙이는 전용 문법

타입 별칭(`type`)으로도 객체 타입을 정의할 수 있지만, 객체의 구조를 다루는 데 특화된 별도 문법이 있다. 바로 **인터페이스(interface)**다. 타입 별칭과 비슷해 보이지만 확장(extends)과 선언 합침이라는 고유한 기능을 제공한다.

---

### 기본 사용법

인터페이스로 객체가 가져야 할 프로퍼티와 메서드의 타입을 선언한다.

```typescript
interface Person {
  name: string;
  age: number;
  sayHi: () => void;
}

const person: Person = {
  name: 'bysu',
  age: 27,
  sayHi: function () {
    console.log("hi");
  },
};
```

`Person` 인터페이스를 타입으로 지정하면, 객체는 반드시 `name`, `age`, `sayHi`를 모두 갖춰야 한다.

> **타입 별칭과의 차이**: 인터페이스는 객체 타입 전용이므로 유니온(`|`)이나 인터섹션(`&`)을 직접 사용할 수 없다. 유니온/인터섹션이 필요하면 `type`을 써야 한다.

---

### 인터페이스 확장 (extends)

여러 인터페이스에 중복 프로퍼티가 있을 때, 상속으로 중복을 제거할 수 있다.

확장 전 — `name`과 `age`가 세 곳에서 반복된다.

```typescript
interface Animal {
  name: string;
  age: number;
}

interface Dog {
  name: string;
  age: number;
  isBark: boolean;
}

interface Cat {
  name: string;
  age: number;
  isScratch: boolean;
}
```

`extends`를 사용하면 공통 프로퍼티를 `Animal`에서 물려받아 각 인터페이스는 고유한 프로퍼티만 선언하면 된다.

```typescript
interface Animal {
  name: string;
  age: number;
}

interface Dog extends Animal {
  isBark: boolean;
}

interface Cat extends Animal {
  isScratch: boolean;
}
```

`Dog`은 `Animal`의 `name`, `age`를 포함하면서 `isBark`를 추가로 갖는다. 클래스 상속과 비슷한 구조다.

---

### 선언 합침 (Declaration Merging)

인터페이스만의 고유 기능이다. **같은 이름의 인터페이스를 여러 번 선언하면 자동으로 하나로 합쳐진다.**

```typescript
interface Person {
  name: string;
}

interface Person {
  age: number;
}

// 위 두 선언이 합쳐져서, Person은 name과 age를 모두 요구한다
const person: Person = {
  name: "",
  age: 27,
};
```

타입 별칭(`type`)은 같은 이름으로 두 번 선언하면 에러가 나지만, 인터페이스는 합쳐진다.

---

### 선언 합침의 활용 — 모듈 보강

선언 합침이 실제로 유용한 장면은 **외부 라이브러리의 타입을 확장**할 때다. 라이브러리가 제공하는 인터페이스에 프로퍼티를 추가해야 하는 상황을 생각해 보자.

```typescript
// 라이브러리가 제공하는 타입
interface Lib {
  a: number;
  b: number;
}

// 내 코드에서 프로퍼티를 추가 (선언 합침)
interface Lib {
  c: string;
}

// a, b, c 모두 사용 가능
const lib: Lib = {
  a: 1,
  b: 2,
  c: 'hello',
};
```

라이브러리 소스를 직접 수정하지 않고도 타입을 확장할 수 있다. 이것이 선언 합침이 존재하는 핵심 이유다.

---

### 정리

| 특성 | 인터페이스 (`interface`) | 타입 별칭 (`type`) |
|---|---|---|
| 객체 타입 정의 | O | O |
| 유니온 / 인터섹션 | X | O |
| `extends` 확장 | O | `&`로 유사하게 가능 |
| 선언 합침 | O | X (중복 선언 에러) |

**객체 구조를 정의**할 때는 인터페이스가 자연스럽고, **유니온이나 원시 타입 조합**이 필요할 때는 타입 별칭을 쓴다. 외부 라이브러리 타입을 확장해야 한다면 인터페이스의 선언 합침이 유일한 선택지다.
