## 타입스크립트의 함수 — 매개변수와 반환값에 타입을 입히는 법

자바스크립트 함수는 매개변수에 어떤 값이든 넘길 수 있고, 반환값도 예측하기 어렵다. 타입스크립트는 함수의 **입력(매개변수)** 과 **출력(반환값)** 에 타입을 지정하여, 함수를 호출하는 시점에 잘못된 인자를 넘기면 컴파일 단계에서 잡아준다.

---

### 함수 타입 정의

타입스크립트에서 함수를 선언하는 두 가지 기본 형태를 보자.

**함수 선언식** — 매개변수 뒤에 `: 타입`을 붙인다. 반환 타입은 타입스크립트가 `return` 문으로부터 추론하므로 생략할 수 있다.

```typescript
function func(a: number, b: number) {
  return a + b;  // 반환 타입은 number로 추론됨
}
```

**화살표 함수** — 문법만 다를 뿐 타입 지정 방식은 동일하다.

```typescript
const add = (a: number, b: number) => a + b;
```

두 경우 모두 `func("1", 2)` 처럼 `string`을 넘기면 컴파일 에러가 발생한다. 이것이 함수에 타입을 붙이는 핵심 이점이다.

---

### 함수 타입 표현식 (Function Type Expression)

함수의 매개변수와 반환 타입을 **별도의 타입으로 분리**할 수 있다. 같은 시그니처를 가진 함수가 여러 개일 때, 매번 타입을 반복하지 않아도 된다.

아래 코드에서 `add`, `sub`, `multiply`는 "숫자 두 개를 받아 숫자를 반환한다"는 동일한 시그니처를 갖는다.

```typescript
const add = (a: number, b: number) => a + b;
const sub = (a: number, b: number) => a - b;
const multiply = (a: number, b: number) => a * b;
```

세 함수 모두 `(a: number, b: number) => number`를 반복하고 있다. 이 시그니처를 타입으로 추출하면 중복을 제거할 수 있다.

```typescript
type Operation = (a: number, b: number) => number;

const add: Operation = (a, b) => a + b;
const sub: Operation = (a, b) => a - b;
const multiply: Operation = (a, b) => a * b;
```

`Operation` 타입이 매개변수와 반환 타입을 이미 정의하고 있으므로, 각 함수에서는 `a`, `b`의 타입을 생략해도 타입스크립트가 자동으로 추론한다. 함수가 늘어날수록 이 방식의 이점이 커진다.

---

### 호출 시그니처 (Call Signature)

함수 타입 표현식과 같은 역할을 하지만, **객체 타입 문법**으로 작성하는 방식이다.

```typescript
type Operation2 = {
  (a: number, b: number): number;
};

const add2: Operation2 = (a, b) => a + b;
const sub2: Operation2 = (a, b) => a - b;
```

화살표(`=>`) 대신 콜론(`:`)을 사용하고, 중괄호(`{}`)로 감싼다는 점이 다르다. 두 방식을 나란히 비교하면 차이가 명확하다.

```
함수 타입 표현식:  (a: number, b: number) => number
호출 시그니처:    { (a: number, b: number): number }
```

기능은 동일하다. 그렇다면 호출 시그니처는 언제 쓸까? 함수이면서 동시에 **프로퍼티를 가진 객체**를 표현할 때 유용하다.

함수 타입 표현식(`type Fn = () => number`)은 순수하게 "호출 가능한 것"만 표현할 수 있다. 하지만 자바스크립트에서 함수는 객체이므로, 함수에 프로퍼티를 붙이는 패턴이 종종 등장한다. 이런 타입은 호출 시그니처로만 표현할 수 있다.

```typescript
type OperationWithDescription = {
  description: string;              // 프로퍼티
  (a: number, b: number): number;   // 호출 시그니처
};
```

이 타입을 만족하는 값을 만들어 보자. 함수에 프로퍼티를 직접 추가해야 하므로 화살표 함수를 바로 대입할 수는 없고, 함수를 먼저 만든 뒤 프로퍼티를 붙인다.

```typescript
// 함수를 먼저 생성한다
const add: OperationWithDescription = (a, b) => a + b;

// 프로퍼티를 추가한다 — 호출 시그니처 덕분에 이 패턴이 타입 안전하게 동작한다
add.description = '두 수를 더하는 연산';

// 함수로서 호출할 수 있고
add(1, 2);              // 3

// 동시에 프로퍼티에도 접근할 수 있다
console.log(add.description);  // "두 수를 더하는 연산"
```

만약 함수 타입 표현식으로 이를 시도하면 프로퍼티를 정의할 곳이 없다.

```typescript
// 함수 타입 표현식 — 호출만 정의할 수 있고, 프로퍼티를 붙일 수 없다
type SimpleOperation = (a: number, b: number) => number;

const sub: SimpleOperation = (a, b) => a - b;
sub.description = '빼기';  // ❌ 'description' 속성이 타입에 없음
```

#### 실전에서는 언제 쓸까?

"함수 + 프로퍼티" 패턴이 와닿지 않을 수 있다. 실제로 자주 마주치는 예시를 보자.

**1) 카운터가 달린 함수** — 함수가 호출될 때마다 몇 번 호출됐는지 추적한다.

```typescript
type CountableFunction = {
  count: number;
  (): void;
};

function createGreeter(): CountableFunction {
  const fn = function () {
    fn.count++;
    console.log(`안녕하세요! (${fn.count}번째 호출)`);
  } as CountableFunction;

  fn.count = 0;
  return fn;
}

const greet = createGreeter();
greet();       // "안녕하세요! (1번째 호출)"
greet();       // "안녕하세요! (2번째 호출)"
greet.count;   // 2
```

외부 변수 없이 함수 자체가 상태를 들고 있다. 호출 시그니처가 없으면 이 패턴에 타입을 붙일 방법이 없다.

**2) HTTP 클라이언트** — `axios`가 대표적인 사례다. `axios(url)` 로 바로 호출할 수도 있고, `axios.get()`, `axios.defaults` 같은 프로퍼티·메서드도 갖고 있다.

```typescript
// axios의 타입 구조를 단순화하면 이런 모습이다
type HttpClient = {
  defaults: { baseURL: string; timeout: number };
  get(url: string): Promise<Response>;
  post(url: string, data: unknown): Promise<Response>;
  (url: string): Promise<Response>;  // 호출 시그니처 — 직접 호출 가능
};
```

`HttpClient` 타입 덕분에 `client('https://...')`로 바로 호출하면서, 동시에 `client.defaults.timeout`으로 설정에도 접근할 수 있다. 이것이 호출 시그니처의 가장 흔한 실전 활용이다.

정리하면, 단순히 함수 타입만 정의한다면 함수 타입 표현식이 더 간결하고, **함수 + 프로퍼티**(호출도 되면서 상태나 설정도 갖는 객체)가 필요한 경우에만 호출 시그니처를 사용하면 된다.

### 함수의 매개변수

타입스크립트 함수의 매개변수는 자바스크립트의 기본값, 나머지 매개변수를 그대로 지원하면서 타입까지 추가할 수 있다.

#### 기본값 매개변수 (Default Parameter)

매개변수에 기본값을 지정하면, 타입스크립트가 기본값으로부터 타입을 추론한다. 별도로 `: string`을 붙이지 않아도 `name`은 `string` 타입이 된다.

```typescript
function introduce(name = 'bysu') {
  console.log(`name: ${name}`);
}

introduce();        // "name: bysu"
introduce('kim');   // "name: kim"
```

#### 나머지 매개변수 (Rest Parameter)

개수가 정해지지 않은 인자를 배열로 받을 때 `...rest` 문법을 사용한다. 타입은 **배열 타입**으로 지정한다.

```typescript
function getSum(...rest: number[]) {
  return rest.reduce((acc, cur) => acc + cur, 0);
}

getSum(1, 2, 3);    // 6
getSum(1, 2, 3, 4); // 10
```

> **`number` vs `Number`**: 소문자 `number`는 원시 타입, 대문자 `Number`는 래퍼 객체 타입이다. 타입스크립트에서는 항상 소문자 `number`를 사용한다.

---

### 정리

| 개념 | 핵심 |
|---|---|
| 함수 타입 정의 | 매개변수에 `: 타입`을 붙이고, 반환 타입은 추론에 맡기거나 명시한다 |
| 함수 타입 표현식 | `type Fn = (a: number) => number`로 시그니처를 분리하여 중복을 제거한다 |
| 호출 시그니처 | `{ (a: number): number }` 형태. 프로퍼티가 필요한 함수 객체에 사용한다 |
| 기본값 매개변수 | `name = 'bysu'`처럼 기본값을 주면 타입도 자동 추론된다 |
| 나머지 매개변수 | `...rest: number[]`로 가변 인자를 배열 타입으로 받는다 |
