## TypeScript 컴파일러 옵션 — tsconfig.json 설정 가이드

### 왜 컴파일러 옵션을 알아야 하나?

TypeScript 파일을 하나씩 `tsc src/index.tsx`로 변환하는 건 파일이 늘어날수록 현실적이지 않다. `tsconfig.json`을 설정해두면 프로젝트 전체의 컴파일 방식을 한 곳에서 관리할 수 있다.

### tsconfig.json 생성

아래 명령어로 기본 설정 파일을 생성한다.

```bash
tsc --init
```

실행하면 프로젝트 루트에 `tsconfig.json`이 만들어지며, 주요 옵션이 주석과 함께 포함되어 있다.

### 주요 설정 항목

| 옵션 | 역할 |
|---|---|
| `include` | 컴파일 대상 폴더/파일 패턴 지정. 예: `["src/**/*"]` |
| `compilerOptions.target` | 컴파일 결과물의 JavaScript 버전 설정 (예: `ES5`, `ES2020`) |
| `compilerOptions.module` | 모듈 시스템 설정 (예: `commonjs`, `ESNext`) |
| `compilerOptions.outDir` | 컴파일된 `.js` 파일의 출력 디렉토리 |
| `compilerOptions.strict` | 타입 검사 엄격도. `true`로 설정하면 모든 strict 계열 옵션이 활성화된다 |

### 모듈 스코프 문제

같은 폴더에 `index.ts`와 `hello.ts`가 있고, 두 파일 모두에 `const a = 1`을 선언하면 **컴파일 에러**가 발생한다. TypeScript가 두 파일을 하나의 전역 스코프(스크립트 모드)로 취급하기 때문이다.

```
a/
├── index.ts   → const a = 1  ❌ 중복 선언 에러
└── hello.ts   → const a = 1  ❌
```

#### 해결 방법 1: `export` 사용

파일에서 `export`를 한 번이라도 사용하면 TypeScript는 해당 파일을 **독립된 모듈**로 인식한다. 각 파일이 자체 스코프를 갖게 되므로 변수명 충돌이 사라진다.

```typescript
// hello.ts
export const a = 1;  // 이제 독립 모듈 → 다른 파일의 a와 충돌하지 않음
```

#### 해결 방법 2: `moduleDetection` 옵션

`tsconfig.json`에서 `moduleDetection`을 설정하면 `export` 없이도 모든 파일을 모듈로 처리할 수 있다.

```json
{
  "compilerOptions": {
    "moduleDetection": "force"
  }
}
```

`"force"`로 설정하면 모든 `.ts` 파일을 모듈로 간주하므로, 매번 `export`를 추가하지 않아도 된다.

### 정리

- `tsc --init`으로 `tsconfig.json`을 생성하고, 매번 파일을 지정하는 대신 `include`로 컴파일 범위를 관리한다.
- `target`, `module`, `outDir`, `strict`가 가장 기본적인 컴파일러 옵션이다.
- TypeScript는 `export`가 없는 파일을 전역 스크립트로 취급한다. 파일 간 변수 충돌을 피하려면 `export`를 사용하거나 `moduleDetection: "force"`를 설정한다.
